# Target survey, 2026-09-30: AI-written Lean formalizations with nontrivial metaprogramming or kernel computation

Sources consulted: the Lean Pool archive (`Vilin97/lean-pool`, 213 projects with a
`provenance` label per project card: 100 AI, 69 human, 37 mixed), the Palomar registry
feed (`data.palomar-registry.org/recent.json`, 200 entries, provenance only where an
abstract discloses it), Tau Ceti (`WHY-Op109/TauCeti`, AI-written by charter), and one
Palomar entry's repository cloned for a closer look. The Zulip "AI authored projects"
channel is not in the public archive index; Lean Pool's own channel carries its
announcements. Metaprogramming counts are over comment-stripped source; `meta` =
`run_cmd` + `macro` + `macro_rules` + `elab` + `syntax` + `MetaM/TacticM/CommandElabM` +
`simproc` + `initialize`. Raw per-project counts: `leanpool-metaprogramming-2026-09-30.json`.

## Finding 1: AI-written Lean Pool projects almost never metaprogram

Of 100 AI-provenance projects, **3** contain any metaprogramming, all trivial (two tactic
macros in a Runge–Kutta project, one `macro_rules` and a small syntax in a hypergraph
project, an attribute syntax in ZetaZeros). The metaprogramming-heavy projects in the
pool (Lentil, MRiscX, Incompleteness, Monlib4, Lean4Itree, GapCVP, SyntheticEuclid4) are
human or mixed. `native_decide`, `unsafe` and `implemented_by` are zero across every AI
project. What AI projects do have is **kernel computation by `decide`**: Erdős 97
octagon (1,067 sites, 102 k lines), 2-coloring-1-round (795), HopfProblem (432, 261 k
lines), FrontierMath hypergraphs (401), Hadwiger–Nelson bounds (383).

## Finding 2: the standout target is the AI-written Four Color Theorem port

`RBarish-UTokyo/FourColorTheorem-Lean4` (Palomar entry, trust `high`; 816 files,
160 k lines; Lean v4.35.0-rc2). Its README's AI disclosure: written essentially entirely
by Claude Opus 5.5 as an agent, reviewed only by a second agent, "no human has reviewed
the mathematics yet". It is a port of Gonthier's Coq proof, so a **reference statement
exists** (`realplane.v`, transcribed into a 220-line `Challenge.lean`), which is the
paired shape our statement rung wants. And it is exactly the kernel-computation and
metaprogramming profile this survey was looking for:

- **16,948 `decide +kernel` sites** (`native_decide` never), 470 plain `decide`, 21
  `set_option maxRecDepth 8000/8192`.
- **An elaboration-time engine** (`FourColor/Engine/Gen.lean`, 958 lines; `QuizData/Lit.lean`):
  `#engine_nets`, `#engine_certify`, `#quizdata_*` commands compute Beneš-network masks and
  reducibility checkpoints with compiled code (`unsafe evalExpr`), inject them as **raw
  `Nat` literals up to 4 MB** (`mkRawNatLit`) in definitions added through `addDecl` under
  custom kernel options (`Elab.async` off, no heartbeat limit), and add theorems whose
  proofs are `Eq.refl true` — kernel evaluation of `tauCheck`, `cnvCheck`, `checkInit/Step/Final`
  over those literals. 633 reducibility certificates are produced this way at build time.
  The docstring's own trust claim is the audit's question: "nothing in this file is
  trusted: a wrong literal only makes a kernel check fail".
- This is precisely the GMP-`Nat` and big-`decide` surface the NSE kernel-trust pass
  named as fragile and found empty there. Here it is the whole proof.
- Palomar's pipeline ran nanoda and con-ron on it; con-leche at its current `master`
  targets Lean v4.33.0, so an independent con-leche run needs either a toolchain bump of
  con-leche or a check that the export format is unchanged at v4.35.

Audit plan if chosen: (1) statement rung against `realplane.v` (PAIRED, by diff);
(2) read the engine as the trust boundary: what `addDecl` adds (definitions and
`Eq.refl true` theorems only?), whether any declaration bypasses the kernel, what the
kernel options change; (3) independent computation of a sample of certificates
outside Lean (the reducibility checks are finite combinatorics — recompute a few
`tauCheck`/`cnvCheck` instances in Python from the same literals); (4) an independent
checker over the full closure (small enough to build here: 160 k lines and Mathlib's
reals only); (5) route walk of the combinatorial core (Birkhoff, discharge, contract),
which is Gonthier's architecture and has a published paper to align with.

## Finding 4: Tau Ceti

1.8 M lines, AI-written by charter. Scan: 13 `elab`, 3 `simproc`, 1 `initialize`, 1,937
`decide`, no `native_decide`; the scanner's `mkProj` (10) and `unsafe` (6) hits are false
positives — `mkProjIso` name matches and `aesop (add unsafe …)` — two patterns to fix in
`scan_repo.py` (word boundary on `mkProj`; exclude `unsafe` inside an `aesop (add …)`
clause). Nothing here points at a nontrivial metaprogramming surface; it is a library,
not a single-theorem claim, so it is a different kind of target.

## Recommendation

Audit the Four Color Theorem port next. It is the only AI-written artifact found with a
genuinely nontrivial metaprogramming layer, it maximises the kernel-computation
exposure, it has a reference statement to pair against, it is small enough to build and
export here, and its authors say plainly that no human has read it.
